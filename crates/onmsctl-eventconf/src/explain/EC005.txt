EC005 — Severity case normalized

Rule
----
The local-schema validator accepts only canonical Title-Case severity
values: `Indeterminate`, `Cleared`, `Normal`, `Warning`, `Minor`, `Major`,
`Critical`. The converter auto-normalizes near-matches (e.g. `WARNING`,
`warning`) to the canonical form and emits an EC005 warning per
normalized event.

This is a WARNING — the YAML is still written. The source XML, however,
remains non-canonical and will continue to trigger EC005 on every
future conversion until edited.

Why
---
Case sensitivity in the schema is intentional: the local YAML is the
authoritative form for declarative management, and consistent case
prevents silent diff churn. Vendor XML files occasionally drift to
uppercase or lowercase as a result of generation tools.

Normalization preserves the operational meaning (a Warning is a Warning
regardless of case) while making the converted YAML pass validation.

How to fix
----------
1. Edit the source XML to use canonical case. For each event flagged by
   EC005:

       <severity>WARNING</severity>   →   <severity>Warning</severity>

2. Re-run the converter. EC005 should no longer fire on those events.

3. If the source XML is generated by an upstream tool, fix the
   generation step. Otherwise the warning will recur on every
   regeneration.

4. If the severity value is genuinely unknown (typo like `Warming` or
   `Mojor`), the converter will emit EC004 (invalid/missing severity)
   instead of EC005. Treat that as a real fix in the XML.
