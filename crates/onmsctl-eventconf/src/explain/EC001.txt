EC001 — Duplicate UEI within source

Rule
----
A single EventSource YAML document MUST NOT declare the same UEI twice.
The local-schema validator (EventSourceLocal::validate) enforces this at
parse time before any HTTP request is issued.

Why
---
In an EventSource, the UEI is the logical event identity — operators
reference it in alarmd rules, automations, downstream consumers, and
runbooks. Two events sharing a UEI within a source create ambiguity:
which definition wins for downstream tooling that keys on the UEI?

Real-world vendor XML legitimately uses duplicate UEIs as a pattern:
multiple SNMP trap types (different MIB OIDs) mapped to a single
semantic event class, disambiguated by the <mask> elements (different
id/generic/specific triplets). The runtime engine resolves each PDU
to exactly one event via non-overlapping mask conditions, but the
downstream ecosystem still sees a single UEI.

This rule preserves the principle that "the UEI is the public name of
the event class" — letting one source file declare two distinct event
classes under the same name creates surprising failure modes for any
ecosystem tooling that doesn't read the masks. The converter surfaces
the duplicates so the operator can choose how to disambiguate.

How to fix
----------
1. RECOMMENDED — rename the UEIs to encode their MIB origin. Example:
       uei.opennms.org/vendor/Cisco/traps/rpsFailed (×2)
   becomes
       uei.opennms.org/vendor/Cisco/traps/fasthub/rpsFailed
       uei.opennms.org/vendor/Cisco/traps/ethernet/rpsFailed

2. Split into separate source files. Each YAML file is a single source;
   moving the duplicated entries into their own files makes the UEIs
   unique per source.

3. ESCAPE HATCH — re-run with --keep-duplicates. The converter writes
   the YAML despite the duplicates; EC001 becomes a warning instead of
   an error. The resulting YAML will NOT pass `onmsctl source apply`
   without further manual edits — apply runs the same validator. Useful
   only as an intermediate for hand-editing.

Background
----------
See the design document at openspec/changes/source-convert-with-migration-
report/design.md for the full rationale. The duplicate-UEI rule was
originally added to catch hand-typed YAML mistakes; the converter
extends it as a teaching tool for vendor-XML migration.
