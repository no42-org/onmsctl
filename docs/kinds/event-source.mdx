Declare one eventconf source per document, with the event definitions it holds.
Targets `/api/v2/eventconf`.

Keep event configuration in git as YAML and push it to Horizon declaratively.
The loop has three steps:

1. `event-source convert` brings existing XML in.
2. `onmsctl apply -f` ships edits out.
3. `event-source export` snapshots the server back to YAML.

## YAML

| Field | Type | Default | Description |
|---|---|---|---|
| **`apiVersion`** | string | required | `eventconf.opennms.org/v1` |
| **`kind`** | string | required | `EventSource` |
| **`metadata.name`** | string | required | Source name, stored on the server verbatim. See the name rules below. |
| **`spec.enabled`** | boolean | `true` | Whether the source is enabled. |
| **`spec.events`** | list | required | Event definitions. At least one entry. |

`metadata.name` rules:

- Only ASCII letters, digits, `.`, `-` and `_`.
- At most 256 characters.
- Must not start or end with `.`, and must not contain `..`.
- `eventconf` and `opennms.catch-all.events` are reserved, compared case-insensitively.
- The vendor segment is at most 128 characters.

Horizon derives `vendor` as the prefix before the first `.` in the name: `cisco.foo` becomes vendor `cisco`.
A name without a `.` becomes the vendor as a whole: `Cisco` becomes vendor `Cisco`.

Fields of an event entry:

| Field | Type | Default | Description |
|---|---|---|---|
| **`uei`** | string | required | Unique event identifier. Must start with `uei.` and have content after it. |
| **`label`** | string | required | Human-readable label. Rejected when empty or whitespace-only. |
| **`severity`** | string | required | One of `Indeterminate`, `Cleared`, `Normal`, `Warning`, `Minor`, `Major`, `Critical`. Case-sensitive. |
| **`description`** | string | none | Per-event description. |
| **`logmsg`** | object | none | `dest` and `text` required, `notify` optional. |
| **`mask`** | object | none | `elements` (`name`, `values`) and `varbinds`. Each varbind sets exactly one of `vbnumber` (positive) or `vboid`. |
| **`operinstruct`** | string | none | Operator instructions. |
| **`mouseovertext`** | string | none | Mouse-over text. |
| **`autoacknowledge`** | object | none | `state` (`on` or `off`) and optional `text`. |
| **`tticket`** | object | none | `state` (`on` or `off`). |
| **`correlation`** | object | none | `state` (`on` or `off`), optional `path`, `cmin`, `cmax`, `cuei`. |
| **`varbindsdecode`** | list | none | `parmid` plus a non-empty `decode` list of `value`/`label` pairs. `parmid` must be unique within an event. |
| **`alarmData`** | object | none | `reductionKey` and `alarmType` required, `autoClean` and `clearKey` optional. See [`alarmType`](#alarmtype). |
| **`snmp`** | object | none | SNMP trap discriminator and metadata. See [`snmp`](#snmp). |
| **`parameters`** | list | none | Static `name`/`value`/`expand` parameters. See [`parameters`](#parameters). |
| **`forwards`** | list | none | Forwarding directives. See [`forwards` and `scripts`](#forwards-and-scripts). |
| **`scripts`** | list | none | Embedded scripts eventd runs on arrival. See [`forwards` and `scripts`](#forwards-and-scripts). |
| **`filters`** | list | none | Regex rewrites of event parameters. See [`filters`](#filters). |

Two events in one source may share a UEI.
The [JSON Schema](../reference/editor-integration.md) lists every field, and [Example](#example) shows a complete document.

## Apply

```sh
onmsctl apply -f cisco.foo.yaml --diff   # push (diff to stderr)
```

`apply` is idempotent: Horizon's upsert replaces events under an existing basename.
When the server's events and `enabled` flag already match, apply reports the source unchanged and sends no upload.
Two documents with the same `metadata.name` in one apply fail the plan, because the upload upserts by name.

**Order:** `EventSource` applies before `EventSourceOrder` and `ThresholdGroup`, so one apply can create a source, place it first, and reference its UEIs from thresholds.

## Inspect and delete

```sh
onmsctl event-source list                          # filter / sort / page
onmsctl event-source get <id>
onmsctl event-source download <id|name> -O out.xml # raw XML for one source
onmsctl event list --source <id>                   # events for a source
onmsctl event-source delete <id>...                # delete sources by id
```

`download` and `export` accept a selector that is either a numeric id or an exact source name.
A value that parses as an integer is always treated as an id, so a source with a numeric name is reachable only by its id.

Snapshot server sources back to git-managed YAML, the reverse of `apply`:

```sh
onmsctl event-source export cisco.foo            # one source → stdout (YAML)
onmsctl event-source export cisco.foo --out ./s/  # one source → ./s/cisco.foo.yaml
onmsctl event-source export --out ./sources/      # every source → one file each
```

Export routes through the `convert` migrator, so it carries the same `EC###` findings, on stderr.
In bulk it is continue-on-error: warnings are written, blocking and download-failed sources are reported and counted, and the exit code reflects the highest severity seen.
`--out` validates every target filename before writing anything: it is all-or-nothing.

Read/raw verbs stay imperative: `event-source list|get|names|names-and-ids|delete`, `event list` (including cross-source `--uei`/`--vendor`), and the raw-XML `event-source upload|download` round trip.
Use the raw-XML round trip for full fidelity when a source carries fields the YAML model doesn't represent yet.

## Convert

```sh
# Single file to stdout
onmsctl event-source convert mevents.xml > mevents.yaml

# Read from stdin (single input; --name required)
cat mevents.xml | onmsctl event-source convert - --name my-source > my-source.yaml

# Batch a directory into per-input YAML files
onmsctl event-source convert ./xml/*.xml --output-dir ./yaml/
```

Conversion emits `EC###`-coded findings on stderr for anything the YAML model doesn't represent.
Run `onmsctl event-source convert --explain <code>` for the rationale behind any finding.
See [Convert findings](#convert-findings) below for the full catalog.

## Convert findings

`event-source convert` parses each event against the local `EventSource` schema and emits findings on stderr.
For an event without a `uei`:

```sh
onmsctl event-source convert bad.events.xml > bad.yaml
```

Expected output (stderr):

```text
─────────────────────────────────────────────────────────────────────
  bad.events.xml → no YAML written
─────────────────────────────────────────────────────────────────────

  EC004  error    event missing required field: uei
    Field: uei
    At:    bad.events.xml:2:3  (event[0])
    Fix: Add the required uei to the event in the source XML; the local schema requires it for a well-formed EventSource.
    For the full rationale: onmsctl event-source convert --explain EC004

─────────────────────────────────────────────────────────────────────
  Summary: 1 events scanned, 0 converted, 1 dropped (0.0% modeled coverage)
  Findings: 1 errors, 0 warnings
  Exit: 2
─────────────────────────────────────────────────────────────────────
```

Finding codes (`EC001`-`EC008`) are stable across releases; `--explain <code>` prints the full rationale for any of them.

| Code | Severity | Meaning |
|------|----------|---------|
| EC001 | warning | Unmodeled direct-child element under `<event>` dropped on conversion. |
| EC002 | error   | Source has zero events. |
| EC003 | error   | Reserved `metadata.name`. |
| EC004 | error   | Event missing a required field. |
| EC005 | warning | Severity case normalized (e.g. `WARNING` to `Warning`). |
| EC006 | error   | Post-conversion validation failed (catch-all). |
| EC007 | error   | `alarm-type` outside the accepted set `{1, 2, 3}`. |
| EC008 | error   | Invalid `metadata.name` (disallowed characters). |

Exit codes: `0` clean, `1` warnings (YAML written), `2` blocking findings (no YAML), `3` usage error before conversion ran.
These replace the global [exit codes](../reference/exit-codes.md#conversion-commands) for `convert`.

Flags:

| Flag | Purpose |
|---|---|
| `-O, --output <path>` | Write the YAML to this file (single input only). Default: stdout. |
| `--output-dir <dir>` | Write one YAML file per input into this directory. |
| `--name <name>` | Override the derived `metadata.name`. Required for stdin input. |
| `--format json` | JSON envelope on stdout instead of the text report: `version`, `input`, `output`, `exit_code`, `findings`, `metrics`, `yaml`. Default: `text`. |
| `--max-bytes 64M` | Override the 16 MiB input cap. |
| `--max-findings 0` | Disable the 1000-finding `EC001` cap (set `<n>` for any other limit). |
| `--force` | Overwrite existing output. |
| `--explain <code>` | Print the full rationale for a finding code and exit. |

`EC001` is the permanent forward-compatibility surface: any direct-child element under `<event>` that the YAML schema doesn't model fires `EC001` rather than silently losing data.
The early modeling gaps (`<snmp>`, `<parameter>`, `<forward>`, `<script>`, `<filters>`) are now first-class.
Remaining unmodeled XSD elements (`<priority>`, `<autoaction>`, `<operaction>`, `<loggroup>`, vendor extensions) keep firing `EC001` until modeled.
For full fidelity today, keep the XML alongside the YAML and use `event-source upload`.
`EC001` is structural-only: it does not detect attribute extensions on modeled elements or enum-value drift on modeled fields.

## Field semantics

### `alarmType`

`spec.events[].alarmData.alarmType` accepts the three known states, in either symbolic (Web UI) form or the integer it maps to:

| Symbolic | Integer |
|---|---|
| `raise` | `1` |
| `resolution` | `2` |
| `unresolvable` | `3` |

Symbolic input is case-insensitive on parse; canonical YAML output is always lowercase.
Anything else fails immediately: unknown symbolic strings (`"problem"`, the alarmd Java alias) or integers outside `{1, 2, 3}`.
YAML inputs reject at deserialize time; eventconf XML inputs produce an `EC007` finding (error, exit 2).

### `snmp`

`spec.events[].snmp` mirrors the eventconf XSD's `<snmp>` element.
Every sub-field is optional.
Practical numeric ranges are documented but not enforced: out-of-range integers round-trip verbatim.
String fields are rejected when empty or whitespace-only.

- `id`: enterprise OID, a free string with no OID-format validation.
- `idtext`: vendor-supplied textual label.
- `version`: common values `v1` / `v2c` / `v3` (free string; variants like `v3-auth-priv` accepted verbatim).
- `generic`: `0..=6` per RFC 1157.
- `specific`: `>= 0`.
- `community`: typically `public`.

### `parameters`

`spec.events[].parameters` mirrors `<parameter name value expand/>`: static per-event configuration eventd attaches to fired events.
Each entry requires `name` and `value`; `expand` is optional and controls whether eventd substitutes `%parm[#N]%`-style placeholders at fire time.
Document order is preserved.

This is distinct from `parmCollection` on a fired event instance, a runtime field on the JSON wire that is not modeled here.

### `forwards` and `scripts`

`spec.events[].forwards` mirrors `<forward state mechanism>target</forward>`: eventd's forwarding directives, validated against the XSD-closed sets:

- `state` is one of `on`, `off`.
- `mechanism` is one of `snmpudp`, `snmptcp`, `xmltcp`, `xmludp`.

Values outside these sets are rejected locally (otherwise Horizon returns a 400).
An empty `forwards: [{}]` entry is rejected; at least one of `state`/`mechanism`/`target` must be set.
A `target` that is empty or whitespace-only is rejected. Omit the field instead.

`spec.events[].scripts` mirrors `<script language>body</script>`: embedded executable logic (typically BeanShell) that eventd runs on event arrival.
`language` is required; `body` is optional and preserved byte-for-byte (use YAML's `|` literal block for multi-line bodies).

:::caution Security note
Shipping executable code via `onmsctl apply` lowers the friction for deploying server-side code execution on Horizon.
The threat surface already exists at the raw eventconf-XML upload path; modeling `<script>` in YAML adds no new authority.
Ensure RBAC on eventconf write access reflects it: anyone who can upload an event source can run code on the Horizon JVM.
:::

### `filters`

`spec.events[].filters` mirrors `<filters><filter eventparm pattern replacement/></filters>`.
Each entry is a regex-replacement rule eventd applies to a named event parameter at fire time:

```
Pattern.compile(pattern).matcher(parmValue).replaceAll(replacement)
```

All three fields are required.
`eventparm` and `pattern` are rejected when empty or when they carry leading or trailing whitespace.
eventd uses the raw value as its lookup key, so padding would prevent matches.
`replacement` may be empty: an empty replacement strips the match.
`pattern` is Java regex; `replacement` supports `$1`/`$2` backreferences.
The YAML is flat (`filters:` directly on the event); the `<filters>` wrapper materializes only on XML render.

`<mask>` versus `<filters>`: `<mask>` selects which events a source applies to (SNMP PDU shape matching on `id` / `generic` / `specific` / varbind values, each an OR-matched value list).
`<filters>` operates after selection, rewriting parameter values on the fired event.

## Apply-time limitations

| # | Limitation | Workaround |
|---|---|---|
| 1 | `spec.description` is rejected at load, because the upload endpoint blanks it. Per-event `description` is modeled and applied. | Set the source description out-of-band through the Horizon REST API or web UI. |
| 2 | Updating a disabled source briefly enables it: the upload lands enabled, then a follow-up call disables it. | `--verbose` warns when this happens. |
| 3 | `spec.vendor` is rejected at load; the vendor is derived from the name. | Encode it as the prefix before the first `.` in `metadata.name`. |
| 4 | `fileOrder` is not accepted on an `EventSource`. | Declare evaluation order with [`EventSourceOrder`](event-source-order.mdx). |

## Errors

Apply reports these at load or plan time, before any upload.

| Message | Probable cause | Recovery |
|---|---|---|
| `spec.fileOrder is not allowed on an EventSource` | The document sets an evaluation order. | Remove the key. Declare the order with an [`EventSourceOrder`](event-source-order.mdx) document. |
| `spec.vendor is not allowed; vendor is server-derived` | The document sets a vendor. | Remove the key. Encode the vendor as the prefix before the first `.` in `metadata.name`. |
| `spec.description cannot be set or preserved through` | The document sets a source description. The upload endpoint blanks it. | Remove the key. Set the description through the Horizon REST API or web UI. |
| `spec.events is empty; refusing to apply an EventSource with no events` | `spec.events` is missing or empty. | Add at least one event. To remove a source, run `onmsctl event-source delete <id>`. |
| `contains invalid characters; only ASCII letters, digits, '.', '-', '_' allowed` | `metadata.name` holds a space, a slash or another character outside the set. | Rename the source. |
| `exceeds 256 chars` | `metadata.name` is longer than 256 characters. | Shorten the name. |
| `must not start with a dot`, `must not end with a dot`, `must not contain consecutive dots` | A dot in the wrong place in `metadata.name`. | Fix the dots. |
| `is reserved by OpenNMS` | `metadata.name` is `eventconf` or `opennms.catch-all.events`, in any case. | Pick another name. |
| `vendor segment '<vendor>' exceeds 128 chars` | The part before the first `.` is longer than 128 characters. | Shorten the vendor prefix. |
| `must start with 'uei.'` | An event `uei` lacks the `uei.` prefix. | Prefix the UEI with `uei.`. |
| `is not a valid OpenNMS severity` | A `severity` outside the seven values, or in the wrong case. | Use one of the listed values, with the exact case. |
| `duplicate EventSource metadata.name across the apply input` | Two documents in one apply share a name. | Keep one document per name. |
| `resolves ambiguously to ids` | More than one server source matches the name. | Delete the extra sources with `onmsctl event-source delete <id>`. |
